# 求职资产聚合与历史时间线方案

## 背景

当前右侧「求职资产」面板直接展示底层产品记录。用户多次上传或诊断同一份简历后，会出现多条名称相同的简历画像，例如多条「张明」。这些记录对审计和追溯有价值，但默认全部摊开会造成两个问题：

- 用户无法判断哪一条是当前应该使用的资产。
- 旧记录如果引用的 artifact 不可用，点击预览会产生误解。

因此 M5 前端阶段先做 UI 层聚合，不改变后端 `CareerProductStore` 的记录模型。

## 目标

- 默认展示「当前可用资产」，而不是每一条历史记录。
- 同一资产的历史记录折叠到时间线弹层。
- 最新记录优先作为当前卡片。
- 保留旧记录的详情、预览、复制 ID 能力。
- 预览失败必须可见，不能静默失败。
- 面板视觉要像产品资产管理区，而不是调试记录清单。

## 视觉原则

参考 Apple HIG 的层级、材质和反馈原则，以及 ChatGPT 类对话产品的轻量信息组织方式，本面板采用以下标准：

- 内容优先：卡片第一眼展示资产类型、当前版本、标题和业务摘要。
- 操作克制：详情、预览、历史是明确按钮，不把技术 ID 放在默认阅读路径上。
- 状态先行：用户点击前能看到 `可预览`、`无文件`、`读取失败`。
- 材质轻量：使用半透明面板、细边框、柔和阴影形成层级，但不使用大面积装饰背景。
- 调试降级：记录 ID、来源会话、证据引用默认折叠，只在需要排障时展开。

## 分组规则

### 简历画像

优先级：

1. `displayName`
2. `raw_text_artifact_id`
3. `meta.source_artifact_id`
4. `resume_profile_id`

同组内按 `meta.updated_at` 倒序，最新一条作为当前卡片。

### 职业画像

优先级：

1. `career_profile_id`
2. `career_goal`

同组内按 `meta.updated_at` 倒序。

### JD 分析

优先级：

1. `meta.source_artifact_id`
2. `company + position`
3. `jd_analysis_id`

### 匹配报告

优先级：

1. `resume_profile_id + jd_analysis_id`
2. `job_fit_report_id`

### 简历版本

优先级：

1. `base_resume_profile_id + target_jd_analysis_id + format`
2. `resume_version_id`

## 组件结构

```text
CareerAssetList
  -> CareerAssetGroup
  -> 当前记录卡片
  -> History 按钮

CareerAssetHistorySheet
  -> HistoryHeader
  -> HistoryTimelineItem[]

HistoryTimelineItem
  -> 时间
  -> 记录标题
  -> artifact 状态
  -> 详情
  -> 预览
  -> 复制 ID
```

## 当前卡片

默认卡片只显示每组最新记录。

卡片顶部展示：

```text
简历画像 active 当前诊断
张明
可预览 · 更新于 05-08 14:28
```

其中 `当前诊断` 表示该组最新记录是默认可用版本；旧版本只在历史弹层里出现。

如果同组存在多条记录，卡片操作区增加：

```text
历史 4
```

点击后打开历史时间线。

## 历史弹层

历史弹层展示同组所有记录：

```text
05-08 14:28  张明  最新
05-08 13:26  张明
05-08 13:24  张明
05-08 12:16  林一凡
```

每条记录操作：

- `详情`
- `预览`
- `复制 ID`

如果记录没有可预览 artifact，则显示 `无预览文件`，不展示预览按钮。

历史项状态：

- 最新一条显示 `当前`。
- 有可读取 artifact 时显示 `可预览`。
- 缺少 artifact 时显示 `无文件`。
- artifact 读取失败后显示 `读取失败`。

## 预览失败状态

预览仍使用：

```text
source_session_id + artifact_id
```

读取失败时弹层展示：

```text
预览失败
artifact 不存在 / session 不存在 / 网络错误
```

后续可以增加预检查，但 M5 先使用读取结果作为状态来源。

## 详情弹层

详情弹层分两层：

- 业务信息：姓名、岗位、技能、报告分数、版本标题等用户可理解字段。
- 调试信息：记录 ID、来源会话、来源文件、证据引用、创建/更新时间。

调试信息默认收起，避免正式体验像内部后台。

## 验收标准

- 同名或同源简历不再在默认列表里平铺多条。
- 默认卡片展示最新记录。
- 卡片上能看到历史数量。
- 点击历史可看到时间线。
- 历史项可以查看详情、预览或复制 ID。
- 没有 artifact 的历史项不展示预览按钮。
- 预览失败时弹层显示错误。
- 顶部数量区分「可用资产」和「底层记录」。
- 默认卡片不暴露长记录 ID。
- 详情弹层默认不铺开调试字段。
