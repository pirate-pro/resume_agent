# M47：产品页面设计原则与重构模板

> 状态：基线原则。后续总览、求职项目、简历资料、JD 匹配、学习计划、笔记、Agent 聊天页都按这套方式重构。目标不是“把页面做漂亮”，而是让每个页面都能清楚回答：这个页面帮用户什么忙、用户下一步该做什么、哪些信息值得注意、哪些信息应该弱化。

## 1. 核心原则

每个页面开发前，先回答 6 个问题：

```text
1. 这个页面帮用户解决什么问题？
2. 用户进入页面时最关心什么？
3. 页面中最重要的信息是什么？
4. 用户最自然的下一步动作是什么？
5. 哪些信息只是辅助，不应该抢注意力？
6. 空态时用户如何知道怎么触发内容？
```

如果这 6 个问题没回答清楚，不应该直接开始堆组件。

## 2. 页面不是数据列表

当前产品最容易走偏的地方是：后端有什么数据，前端就把数据全部摆出来。

正确方式：

```text
数据是原料，不是页面结构。
页面结构来自用户任务。
组件位置来自注意力优先级。
按钮文案来自用户目标，不来自技术动作。
```

例如：

```text
不要：
  Agent
  执行
  处理
  查看记录

要：
  生成定制简历
  分析岗位差距
  记录学习进度
  开始复盘
  查看关联任务
```

## 3. 每个页面的产品骨架

每个主页面都按这个结构设计：

```text
Page Mission
  这个页面存在的理由。

Primary User Job
  用户进入页面最想完成的事情。

Attention Hierarchy
  一级、二级、三级、四级信息分别是什么。

Primary Actions
  最重要的 1 到 2 个动作。

Secondary Actions
  可以做，但不应该抢主线的动作。

Empty State
  没有数据时如何解释、如何引导。

Data Trigger
  页面内容从哪里来，什么事件会生成或更新。

Responsive Behavior
  桌面、平板、手机如何降级。
```

## 4. 注意力层级规范

页面上不能所有卡片都一样重。

```text
一级注意力
  当前判断、核心状态、今天必须做的事。
  位置：首屏上方、Hero、右侧今日推进、主列表第一位。
  样式：大标题、清晰 CTA、少量关键数字。

二级注意力
  主体列表、任务看板、路线、关键资产。
  位置：主工作区。
  样式：标准卡片、状态清楚、可展开详情。

三级注意力
  解释层、辅助建议、风险说明、历史摘要。
  位置：主体下方或右侧栏。
  样式：轻卡片、小标签、低阴影。

四级注意力
  已完成、已忽略、归档、内部编号、完整证据引用。
  位置：详情、筛选、更多菜单。
  样式：不常驻主页面。
```

## 5. 按钮层级规范

按钮必须体现用户目标和操作优先级。

```text
主按钮
  页面最重要动作，一屏最多 1 到 2 个。
  使用实心主色。

次按钮
  常用但非主线动作。
  使用描边或浅色底。

低权重动作
  删除、忽略、取消、归档、改时间。
  放到更多菜单或详情页里。

Agent 动作
  可以有 AI 标识，但按钮文案必须是用户目标。
```

例子：

```text
不好：
  Agent
  让 Agent 处理
  执行

更好：
  生成任务
  分析差距
  优化简历
  生成面试题
  安排复盘
```

## 6. 空态规范

空态不是一句“暂无数据”。空态必须回答：

```text
这个区域是做什么的？
为什么现在没有？
用户下一步可以做什么？
系统什么时候会自动生成？
```

空态分三类：

```text
解释态
  用户还没有开始相关流程。
  低权重，主要解释用途。

引导态
  用户已经具备前置条件，但还没生成内容。
  中权重，提供下一步按钮。

异常态
  按正常流程应该有内容，但没有。
  高权重，提示用户补救或重新生成。
```

例如学习计划：

```text
短板空态：
  完成 JD 匹配或面试复盘后，这里会显示影响岗位匹配的能力缺口。

复盘空态：
  完成学习任务后，这里会自动安排一次回顾，帮助你确认是否真正掌握。
```

## 7. 数据触发规范

每个页面模块都要明确数据来源和触发事件。

```text
数据来源
  API / store / Agent 工具 / 用户手动输入 / 后端确定性服务。

触发事件
  创建、更新、完成、归档、复盘、上传、分析、匹配。

是否自动
  自动生成、用户确认后生成、只能手动生成。

是否幂等
  重复触发是否复用旧记录，还是创建新记录。
```

不允许出现这种模糊逻辑：

```text
页面上有一个按钮，点了就交给 Agent 判断。
```

应该改成：

```text
页面上有一个明确目标动作。
前端知道这个动作的输入、输出和成功后的页面变化。
如果需要 Agent，只负责生成内容或建议，不负责决定产品状态机。
```

## 8. 页面布局规范

桌面端主结构：

```text
左侧产品导航
中间主工作区
右侧上下文栏
```

主工作区顺序：

```text
页面标题与核心动作
状态 Hero / 当前判断
核心业务模块
解释与巩固模块
历史与辅助信息
```

右侧栏只放和当前页面强相关的上下文：

```text
当前项目
今日推进
推荐动作
关联资产
最近更新
```

不要把所有页面都做成“卡片堆叠”。卡片只用于承载具体对象、工具面板、右侧上下文和重复项。

## 9. 响应式规范

桌面：

```text
三栏布局。
右侧栏常驻。
主操作和上下文同时可见。
```

平板：

```text
左侧导航可折叠。
右侧栏下移或变成抽屉。
主工作区保持完整。
```

手机：

```text
单列布局。
顺序优先级：
  当前判断
  今天要做什么
  主列表 / 看板
  解释模块
  关联资产
```

移动端不要简单缩小桌面卡片，要重新排序注意力。

## 10. 页面级重构模板

后续每个页面先按这个模板写方案：

```text
## 页面使命

## 用户进入页面时的第一问题

## 页面帮用户完成的 3 件事

## 一级 / 二级 / 三级 / 四级信息

## 主按钮和次按钮

## 空态、引导态、异常态

## 数据来源和触发事件

## 桌面 / 平板 / 手机布局

## 不做事项

## 验收标准
```

## 11. 各页面初步方向

### 总览

```text
页面使命：
  告诉用户当前求职推进是否健康，今天最该做什么。

一级注意力：
  当前求职状态、最重要的下一步、最高风险岗位。

不应该变成：
  所有模块的摘要堆叠。
```

### 求职项目

```text
页面使命：
  管理每个岗位从投递、匹配、简历、面试到 offer 的推进状态。

一级注意力：
  当前最活跃项目、项目阶段、下一步动作。

不应该变成：
  简单岗位列表。
```

### JD 匹配

```text
页面使命：
  让用户知道当前简历和岗位要求的差距，并生成可执行补救动作。

一级注意力：
  匹配分、关键优势、关键风险、下一步推荐。

不应该变成：
  分数字段和报告文本堆叠。
```

### 简历资料

```text
页面使命：
  管理不同岗位版本的简历，并让用户知道每个版本为什么改、适配什么岗位。

一级注意力：
  当前推荐简历版本、最近优化点、关联岗位。

不应该变成：
  文件列表。
```

### 学习计划

```text
页面使命：
  把岗位差距转成可执行学习任务，并通过复盘验证学习是否有效。

一级注意力：
  当前学习状态、今天要推进的任务、到期复盘。

不应该变成：
  任务卡片列表 + Agent 按钮。
```

### 笔记

```text
页面使命：
  沉淀面试复盘、岗位信息、学习记录和可复用资料。

一级注意力：
  最近重要笔记、关联项目、可转化动作。

不应该变成：
  没有分类和上下文的笔记列表。
```

### Agent 聊天

```text
页面使命：
  承载自由问答和复杂协作，但不替代每个产品页面的主操作。

一级注意力：
  当前会话目标、流式回答、必要的工具/Agent 过程。

不应该变成：
  所有产品动作默认跳转的兜底页面。
```

## 12. 验收标准

每个页面重构后至少满足：

```text
1. 用户不看文档也知道这个页面是干什么的。
2. 用户能一眼看到最重要状态和下一步动作。
3. 空态能告诉用户如何产生内容。
4. 主按钮不会把用户无理由跳到聊天页。
5. Agent 入口是增强能力，不是产品逻辑兜底。
6. 重要信息突出，辅助信息克制。
7. 手机端仍能按正确顺序完成主流程。
```

## 13. 关键结论

UI 不是表层美化，而是产品逻辑的外化。

```text
先知道页面要帮用户做什么，
再决定信息怎么分层，
再决定按钮放在哪里，
最后才是颜色、圆角、阴影和组件。
```

后续所有页面都按这个顺序重构。
