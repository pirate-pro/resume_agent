# M48 学习计划页内容与交互梳理

日期：2026-05-30

目标：先把当前学习计划页里所有区块、按钮、数据来源和真实行为讲清楚，不直接改 UI。后续根据这份文档逐项确认产品逻辑，再做界面重构，避免继续出现“按钮看起来一样，但实际不是一回事”的混乱。

## 1. 当前页面的真实定位

当前页面看起来想做的是：

> 围绕一个求职项目，把岗位差距拆成学习路线、学习任务、短板和复盘安排，让用户持续推进。

但当前实现里混入了三种不同产品形态：

1. 数据看板：展示学习路线、任务、短板、复盘、统计数量。
2. 任务管理：拖动任务、记录进度、新建任务、删除任务。
3. Agent 入口：多个“生成建议 / AI 建议 / 建议”按钮把用户重新拉回 AI 生成。

问题是：这三种形态没有建立清晰层级。尤其是“建议”这个词被用在很多地方，但含义不同，导致用户不知道自己点的是：

- 生成新的学习任务？
- 拆解当前任务？
- 生成短板建议？
- 生成复盘安排？
- 让 Agent 接管当前页面？

## 2. 当前页面数据来源

页面主数据来自 `careerWorkbenchProvider`：

- `selectedApplicationSummary`
- `selectedApplicationDetail`
- `detail.learning`

学习相关数据结构：

- `CareerWorkbenchLearningPlanView`：学习路线。
- `CareerWorkbenchLearningTaskView`：学习任务。
- `CareerWorkbenchWeaknessView`：短板与证据缺口。
- `CareerWorkbenchReviewView`：复盘安排。

当前页面只读这些结构，然后通过几个动作修改：

- 创建学习任务：`createLearningTask`
- 创建学习进度记录：`createLearningCheckin`
- 更新任务状态：`updateLearningTaskState`
- 删除学习任务：`archiveLearningTask`
- Agent 生成建议：`onSendPrompt(prompt)`，然后刷新 workbench

注意：当前大部分“生成建议”并不是直接调用结构化学习 API，而是给 Agent 发 prompt，依赖 Agent 自己决定是否创建任务、短板或复盘。因此点击后可能出现：

- 只在会话里生成文字，没有新增学习资产。
- 新增了任务，但用户不知道为什么新增。
- 没新增任何东西，但页面只是刷新。

桌面端：

## 4. 区块逐项梳理

### 4.1 页面 Header

位置：页面最上方。

内容：

- 标题：`学习计划`
- 标签：`补短板`
- 说明：`把岗位差距拆成今天能推进的学习任务，持续提升面试准备度。`
- 按钮：
  - `刷新`
  - `生成建议`
  - `新建任务`

当前按钮行为：

- `刷新`：刷新 workbench 数据。
- `生成建议`：调用 `_sendRecommend(surface: 'header')`。
- `新建任务`：打开手动创建任务弹窗。

当前问题：

- Header 里的 `生成建议` 是页面级建议，但没有说明“生成什么建议”。
- `surface: 'header'` 当前没有对应的内联状态展示位置，所以点击后可能没有明显反馈。
- Header 已经有 `新建任务`，旁边再放 `生成建议`，用户会以为它也是创建任务，但实际只是给 Agent 发 prompt。

建议定位：

- Header 只保留全局、确定性动作：`刷新`、`新建任务`。
- 页面级 AI 动作如果保留，应命名为 `AI 生成任务草案`，并且只放一个主入口，不要在多个区块重复。

### 4.2 当前学习状态 Hero

位置：Header 下方大卡片。

内容：

- 标题：`当前学习状态`
- 描述：围绕目标岗位补齐关键技能与面试证据。
- 标签：
  - 目标岗位
  - 待推进任务数量
  - 高优先短板数量
- CTA：`生成下一步建议`
- 圆形进度：整体学习进度
- 学习判断：根据任务、短板、待办生成一句判断
- 高优先短板 mini rows

当前按钮行为：

- `生成下一步建议`：调用 `_sendRecommend(surface: 'hero')`。

当前问题：

- `生成下一步建议` 和 Header 的 `生成建议` 本质接近，但文案不同。
- `surface: 'hero'` 当前没有对应的内联状态展示位置，点击后反馈不稳定。
- Hero 是页面最显眼位置，应该承载用户最重要的下一步，而不是泛泛生成建议。

建议定位：

- Hero 只保留一个主 CTA：`继续推进今日任务` 或 `生成今日计划`。
- 如果当前已有待推进任务，优先引导用户去任务看板，而不是再生成。
- 如果没有任务，才显示 `生成学习任务`。

### 4.3 关联求职项目

位置：Hero 下方。

内容：

- 标题：`关联求职项目`
- 横向项目 chip
- chip 显示：
  - 项目名称
  - 学习任务数量
  - loading 状态

当前行为：

- 点击项目 chip 会切换当前求职项目。

当前问题：

- 这个区块作用比较清晰。
- 但它的位置很高，视觉权重略重。用户主要任务不是切换项目，而是推进学习。

建议定位：

- 保留。
- 作为上下文切换组件，视觉应该更轻，不要抢主任务区注意力。

### 4.4 指标卡片

位置：关联项目下方。

内容：

- 学习路线数
- 待推进任务数
- 已完成任务数
- 复盘安排数

当前行为：

- 纯展示，不可点击。

当前问题：

- 指标能说明资产规模，但不能直接指导下一步。
- `学习路线` 为 0 时显示待生成，但没有直接说明如何生成。

建议定位：

- 保留，但变成更轻的状态概览。
- 可以考虑让指标卡可点击跳转到对应区块，但需要明确 hover 和 cursor。

### 4.5 学习路线

位置：指标卡下方。

当前展示：

固定四阶段：

```text
01 基础夯实
02 LangChain / RAG
03 Agent 工程化
04 面试冲刺
```

每个阶段展示：

- 阶段标题
- 阶段副标题
- 进度条
- 状态：未开始 / 进行中 / 已完成
- 百分比

当前生成逻辑：

- 阶段不是完全来自后端路线数据，而是前端根据任务文本做关键词归类。
- 关键词命中：
  - 面试 / 复盘 / mock / 题 / interview => 面试冲刺
  - agent / 工具 / workflow / langgraph / 多 agent => Agent 工程化
  - rag / langchain / 检索 / 向量 / 知识库 / retrieval => LangChain / RAG
  - 其他 => 基础夯实
- 阶段进度根据该阶段任务的完成数量计算。
- 如果没有阶段任务，就使用 fallback 值。

当前问题：

- 这不是用户真实创建的路线，而是前端临时推导。
- 阶段名称固定，后续不同岗位会不准确。
- 新增任务后路线进度可能看起来不符合用户预期，因为它依赖关键词和整体进度 cap。

建议定位：

- 学习路线应该是“学习任务的分组和路径”，不是写死四个阶段。
- 后续应由后端/Agent 生成结构化 `LearningPlan` 和 `phase`，前端只展示。
- 如果没有真实路线，就显示“待生成路线”，不要假装已有完整路线。

### 4.6 学习任务看板

位置：学习路线下方，是页面核心。

列：

- `进行中`
- `待推进`
- `已完成`

当前状态分类：

- `doing` / `in_progress` => 进行中
- `done` / `completed` => 已完成
- 其他 open task => 待推进

当前行为：

- 任务卡可以长按拖动。
- 拖到不同列会调用 `updateLearningTaskState`。
- 已完成任务也可以拖出。
- 点击任务卡打开详情弹窗。

任务卡内容：

- 图标
- 标题
- 描述/完成标准/进展摘要
- 状态标签
- 优先级标签
- 预计分钟数
- 技能标签
- 进度条
- 按钮：
  - `记录`
  - `建议`

#### 任务卡里的 `记录`

当前作用：

- 打开学习进度记录弹窗。
- 用户填写学习时长、进展、阻塞、下一步状态。
- 保存后创建 check-in，并可更新任务状态。

产品定位：

- 这是确定性动作，应该保留。
- 它是任务卡最重要动作。

当前问题：

- 文案 `记录` 稍短，可以考虑改为 `记录进度`。
- 按钮尺寸当前比进度条显眼，这个可以接受，因为它是主操作。

#### 任务卡里的 `建议`

当前真实行为：

- 它接的是任务看板的 `onRecommend`。
- 也就是 `_sendRecommend(surface: 'tasks')`。
- 它不是针对当前这条任务生成建议，而是页面级“生成学习任务建议”。

这就是当前最严重的语义问题之一：

> 用户在某个任务卡里点“建议”，直觉上以为是针对这个任务；但代码实际发的是整页任务建议。

建议定位：

- 任务卡里的按钮不应叫 `建议`。
- 如果要保留任务级 AI，应改成：
  - `AI 拆解`
  - 或 `下一步`
- 点击后必须针对当前任务，而不是整页。
- 结果应显示在当前任务详情弹窗或任务卡下方，不应显示在页面顶部，也不应刷新整个页面后无痕消失。

### 4.7 任务详情弹窗

打开方式：点击任务卡。

内容：

- 标题
- 状态、优先级、预计分钟
- 任务要求
- 完整说明
- 完成标准
- 进展记录
- 技能标签

底部按钮：

- `删除任务`
- `生成建议`
- `记录进度`

#### 详情弹窗里的 `生成建议`

当前真实行为：

- 调用 `_sendTaskAgentAdvice`
- prompt 里包含当前任务 id、标题、说明、完成标准、状态。
- 这是任务级建议，和任务卡里的 `建议` 不是同一逻辑。

当前问题：

- 它会关闭弹窗，然后在任务看板模块显示一个内联状态。
- 用户在弹窗里点击，却在弹窗外看状态，不符合“就地生成”的预期。
- 文案仍然叫 `生成建议`，和页面级建议混淆。

建议定位：

- 改名为 `AI 拆解任务`。
- 点击后不关闭弹窗。
- 在弹窗里生成一个 `AI 拆解结果` 区块。
- 拆解结果可包含：
  - 下一步行动
  - 子步骤
  - 预计耗时
  - 验收标准
  - 推荐资料或练习
- 后续再提供：
  - `保存为子任务`
  - `复制`
  - `记录进度`

### 4.8 短板与证据缺口

位置：页面底部左侧。

产品意义：

> 告诉用户为什么要学这些任务。它不是任务本身，而是岗位匹配、简历诊断、面试复盘后沉淀出的能力缺口。

当前状态：

- 如果有 active/open weakness：
  - 展示短板卡片
  - 每张卡展示标题、来源、状态、关联任务数、描述、技能标签
  - 卡片按钮：`生成任务`
- 如果没有待处理短板：
  - 展示空状态
  - 标题：`还没有待处理短板` 或 `当前短板已处理`
  - 说明短板来源
  - 主按钮：`生成学习建议`
  - 次按钮：`查看复盘笔记`

当前按钮：

1. 区块右上角 `生成建议`
2. 空状态左下角 `生成学习建议`

当前真实行为：

- 当没有 open weakness 时，这两个按钮都调用同一个 `onRecommend`。
- 也就是 `_sendRecommend(surface: 'weakness')`。
- 两个按钮没有功能区别。

这就是截图里用户指出的问题：

> 同一个区块出现两个“生成建议”，一个右上角，一个左下角，但没有区别。

当前布局问题：

- 右上角通常应该放低权重的区块操作。
- 空状态里的主按钮应该是当前空状态的核心引导。
- 两个按钮同时出现会让用户误以为它们不同。

建议定位：

- 没有待处理短板时：只保留空状态主按钮。
  - 文案建议：`从匹配报告生成短板`
  - 或 `生成短板与学习任务`
- 有待处理短板时：右上角可以改成 `全部转任务`，但要谨慎，因为这会批量创建任务。
- 单个短板卡片里的按钮应叫 `转成任务`，不是 `生成任务`，因为它是把一个短板转化为学习任务。
- 如果目前只是打开手动新建任务弹窗，那按钮文案应是 `新建任务` 或 `手动转任务`，不能暗示系统会自动基于短板生成。

### 4.9 复盘安排

位置：页面底部右侧。

产品意义：

> 让用户完成任务后回头确认是否真的掌握，并把成果沉淀成面试表达、笔记或简历证据。

当前状态：

- 如果有 active review：
  - 展示复盘行
  - 显示复盘标题、到期状态、复盘类型、摘要
  - 按钮：`开始复盘`，但当前是 disabled
- 如果没有 active review：
  - 展示空状态
  - 如果有已完成任务，显示 `可以安排一次复盘`
  - 按钮：`生成复盘建议`
  - 如果没有已完成任务，不显示按钮

当前按钮行为：

- `生成复盘建议` 调用 `_sendRecommend(surface: 'review')`。

当前问题：

- `开始复盘` 是 disabled，会让用户困惑。
- `生成复盘建议` 的结果仍依赖 Agent 是否落库。
- 复盘区和短板区都叫“建议”，但产品意义不同。

建议定位：

- 如果没有复盘，按钮应叫 `安排复盘`。
- 如果已经有复盘，按钮应叫 `开始复盘` 或 `记录复盘结果`，并可用。
- 复盘不应只是建议，而应是一个确定性日程/记录动作。

### 4.10 右侧栏：今日推进

位置：右侧栏第一块。

内容：

- 标题：`今日推进`
- subtitle：待办数量
- 右上角：`生成建议`
- 任务列表：
  - title
  - subtitle
  - badge
  - 主动作：`记录`
  - 次动作：`AI 建议`

当前真实行为：

- 右上角 `生成建议` 调用 `_sendRecommend(surface: 'rail')`。
- 每条任务的 `AI 建议` 也调用同一个 `onRecommend`。
- 也就是说，右侧单条任务的 `AI 建议` 不是针对该任务，而是右侧栏级/页面级建议。

当前问题：

- 和任务卡里的 `建议` 同类问题：看起来是任务级，实际不是任务级。
- `surface: 'rail'` 当前没有对应内联状态展示位置。
- 右侧栏本应是“今天该做什么”，不应放一个泛化生成入口。

建议定位：

- 今日推进里每条任务应该只有两个明确动作：
  - `记录进度`
  - `查看详情`
- 如果放 AI，必须是任务级：
  - `AI 拆解`
  - `帮我开始`
- 右上角不建议再放 `生成建议`，否则和主页面重复。

### 4.11 右侧栏：关联项目

内容：

- 当前项目标题
- 项目摘要
- `查看`

当前行为：

- 跳到求职项目页。

问题：

- 作用清晰。
- 可以保留。

### 4.12 右侧栏：关联笔记

内容：

- 最近笔记
- `查看全部`

当前行为：

- 跳到笔记页。

问题：

- 作用清晰。
- 但后续最好支持从当前学习任务直接关联/新建笔记。

### 4.13 右侧栏：学习资产

内容：

- 路线数量
- 任务数量
- 短板数量
- 复盘数量

当前行为：

- 纯展示。

问题：

- 可保留，但视觉应更轻。
- 资产统计不是主任务，不应和今日推进抢权重。

## 5. 当前所有“建议/生成”入口清单

| 位置 | 当前文案 | 当前真实行为 | 是否有内联反馈 | 问题 |
|---|---|---|---|---|
| Header | 生成建议 | `_sendRecommend(surface: header)`，页面级任务建议 | 没有 | 泛化、重复、点击后反馈弱 |
| Hero | 生成下一步建议 | `_sendRecommend(surface: hero)`，页面级任务建议 | 没有 | 和 Header 重复，位置太重要但语义不清 |
| 学习任务区右上 | 生成建议 | `_sendRecommend(surface: tasks)`，页面级任务建议 | 有，在任务区 | 可以保留，但文案应更明确 |
| 任务卡 | 建议 | 当前也是页面级 `_sendRecommend(surface: tasks)` | 有，在任务区 | 看起来任务级，实际页面级，严重误导 |
| 任务详情弹窗 | 生成建议 | `_sendTaskAgentAdvice`，任务级建议 | 不在弹窗内，在任务区 | 语义接近正确，但展示位置错 |
| 短板区右上 | 生成建议 | `_sendRecommend(surface: weakness)` | 有，在短板区 | 和空状态主按钮重复 |
| 短板空状态 | 生成学习建议 | `_sendRecommend(surface: weakness)` | 有，在短板区 | 和右上按钮同功能 |
| 复盘空状态 | 生成复盘建议 | `_sendRecommend(surface: review)` | 有，在复盘区 | 语义尚可，但更应是“安排复盘” |
| 今日推进右上 | 生成建议 | `_sendRecommend(surface: rail)` | 没有 | 和页面主入口重复 |
| 今日推进任务行 | AI 建议 | 当前也是 `_sendRecommend(surface: rail)` | 没有 | 看起来任务级，实际不是 |

结论：

当前至少有 10 个“建议/生成”入口，其中很多是同一个功能的不同文案，很多又看起来像任务级但实际是页面级。这是页面显得乱的核心原因。

## 6. 当前按钮设计问题

### 6.1 命名问题

当前过度使用：

- `建议`
- `生成建议`
- `AI 建议`
- `生成学习建议`
- `生成下一步建议`

这些词太相似，但背后动作不同。

建议统一成四类动作：

| 类型 | 推荐文案 | 作用 |
|---|---|---|
| 页面级生成 | 生成学习任务 | 从岗位差距生成新任务 |
| 任务级辅助 | AI 拆解 | 拆解当前任务下一步 |
| 用户进度 | 记录进度 | 用户自己更新学习进展 |
| 短板转化 | 转成任务 | 把短板变成可执行任务 |
| 复盘动作 | 安排复盘 / 开始复盘 | 建立或执行复盘 |

### 6.2 颜色问题

当前按钮颜色大致是：

- 主按钮：绿色
- 次按钮：绿色描边
- 删除：红色文字

问题：

- AI 动作和普通次动作都用绿色描边，区分不明显。
- 同一个区块里有多个绿色按钮，用户不知道哪个最重要。

建议：

- 用户主路径：绿色实心。
  - `记录进度`
  - `新建任务`
  - `生成学习任务`，仅在无任务时
- AI 辅助：浅紫或绿色描边，但配 `auto_awesome` 图标。
  - `AI 拆解`
  - `生成草案`
- 危险动作：红色文字或红色描边。
  - `删除任务`
- 低优先跳转：灰色/绿色文字按钮。
  - `查看全部`
  - `查看复盘笔记`

### 6.3 位置问题

当前问题：

- 短板区右上和空状态左下同时出现同一功能。
- 今日推进右上和每个任务行都出现建议，但实际同一功能。
- Hero 和 Header 都出现页面级建议。

建议原则：

- 一个功能只出现一个主入口。
- 区块右上角只放“管理/查看全部/轻操作”。
- 空状态主按钮放在空状态正文后面。
- 任务级按钮必须靠近任务，不要放到区块右上。

### 6.4 Hover / Focus / Disabled 问题

当前代码主要使用 Flutter 默认按钮 hover。

已经有：

- `InkWell` 点击涟漪。
- 任务卡拖动时有 grab cursor。
- DragTarget 接受时列边框变色。

缺少明确设计：

- 按钮 hover 背景、边框、文字颜色没有独立产品规范。
- AI 按钮 hover 没有和普通按钮区分。
- disabled 状态有些地方只是灰掉，但用户不知道为什么不可用。
- 右侧栏中的 `开始复盘` 当前 disabled，但没有说明原因。

建议：

- 所有可点击按钮 hover：
  - 绿色实心：hover 深绿 `#0B8A5F`
  - 绿色描边：hover 浅绿底 `#E8F7F0`
  - AI 辅助：hover 浅紫或浅绿底，并保持图标高亮
  - 危险：hover 浅红底
- disabled 必须配原因：
  - tooltip 或旁边提示
  - 例如 `完成任务后可安排复盘`

## 7. 应该重新定义的产品语义

我建议把页面动作拆成三层，而不是都叫建议。

### 7.1 页面级：生成学习任务

触发位置：

- 只保留一个入口。
- 推荐放在 Hero 或学习任务区右上。

作用：

- 根据当前求职项目、匹配报告、短板、笔记，生成 1-3 个学习任务。

不应该：

- 出现在每个任务卡里。
- 出现在右侧今日推进每一项里。

推荐文案：

```text
生成学习任务
```

### 7.2 任务级：AI 拆解

触发位置：

- 任务详情弹窗内。
- 任务卡上可以保留一个轻按钮，但要明确是针对当前任务。

作用：

- 把当前任务拆成下一步行动、练习方式、产出物和验收标准。

推荐文案：

```text
AI 拆解
```

结果展示：

- 就地显示在任务详情弹窗里。
- 不要跳到顶部。
- 不要跳聊天页。

### 7.3 短板级：转成任务

触发位置：

- 单个短板卡片。
- 有多个短板时可有 `批量转任务`，但要谨慎。

作用：

- 把一个岗位差距变成一个可执行学习任务。

推荐文案：

```text
转成任务
```

### 7.4 复盘级：安排复盘 / 开始复盘

触发位置：

- 复盘安排区。

作用：

- 完成任务后安排复盘。
- 到期后记录复盘结果。

推荐文案：

```text
安排复盘
开始复盘
```

## 8. 建议的页面信息优先级

从用户进入页面的视角，最重要的问题是：

1. 我现在该做什么？
2. 为什么要做这个？
3. 做到什么程度算完成？
4. 做完后怎么沉淀成求职竞争力？

因此页面优先级应是：

```text
P0 今日要推进的任务
P0 当前任务进度与状态
P1 学习路线 / 当前阶段
P1 短板原因
P1 复盘安排
P2 关联项目 / 关联笔记 / 学习资产统计
```

当前页面的问题是：

- 学习路线、指标、关联项目占了比较靠上的位置。
- 任务看板是核心，但被放在中段。
- 短板与复盘很重要，但现在像两个补丁卡片。

## 9. 后续修改建议顺序

建议先不要继续加功能，先做语义收敛。

### 第一步：统一所有按钮语义

把所有“建议”入口改成明确动作：

- 页面级：`生成学习任务`
- 任务级：`AI 拆解`
- 短板级：`转成任务`
- 复盘级：`安排复盘`
- 进度级：`记录进度`

### 第二步：去掉重复入口

优先删除/隐藏：

- Header 的 `生成建议`
- Hero 的 `生成下一步建议` 和任务区的 `生成建议` 二选一
- 短板区右上和空状态左下重复按钮二选一
- 右侧栏 `今日推进` 里的泛化 `生成建议`

### 第三步：任务级 AI 结果就地展示

任务详情弹窗点击 `AI 拆解` 后：

- 不关闭弹窗。
- 在弹窗中出现生成中状态。
- 生成完成后显示拆解结果。
- 后续再考虑保存为子任务。

### 第四步：短板和复盘改成确定性动作

短板：

- `转成任务` 应该打开带短板预填的任务创建弹窗，或直接创建草案。

复盘：

- `安排复盘` 应该创建 review schedule。
- `开始复盘` 应该打开复盘记录弹窗。

### 第五步：重新调整页面层级

任务看板应更靠前，短板/复盘要解释“为什么学”和“学完怎么验证”，右侧栏降低重复动作。
